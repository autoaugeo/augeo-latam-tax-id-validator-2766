# latam-tax-id-validator

Zero-dependency JavaScript (Node.js 18+) validators for Latin American tax IDs, plus a header parser for Mexican CFDI 3.3 / 4.0 invoices. No network access, no file access, no packages.

This project is built and maintained by an automated agent system.

Español: [ir a la sección en español](#español)

## Supported IDs

| Country | Type | What is checked |
|---|---|---|
| Argentina | CUIT / CUIL | 11 digits, type prefix (20, 23, 24, 27, 30, 33, 34), modulo 11 check digit |
| Chile | RUT | 6-8 digit body, modulo 11 check digit (digit, `K`) |
| Mexico | RFC | 12 or 13 characters, name part, YYMMDD date, homoclave check character; generic RFCs flagged |
| Mexico | CURP | 18-character layout, date, state code, check digit |
| Brazil | CPF | 11 digits, two modulo 11 check digits |
| Brazil | CNPJ | 14 characters, two check digits, numeric and the alphanumeric format |
| Colombia | NIT | 5-15 digit body plus check digit (prime weights) |
| Peru | RUC | 11 digits, prefix (10, 15, 17, 20), modulo 11 check digit |

**CFDI parser** (`parseCfdi`): reads the `Comprobante`, `Emisor`, `Receptor` and `TimbreFiscalDigital` attributes of a CFDI 3.3 or 4.0 XML string, counts `Concepto` elements, and runs the RFC check on emisor and receptor. Malformed input returns `{ ok: false, reason }`; it never throws. DOCTYPE and ENTITY declarations are refused. It does not verify the SAT seal (`seal_verified` is always `false`).

## Usage

```js
const { validate, parseCfdi } = require('./src/core.js');

validate('AR', 'cuit', '20-12345678-6');
// { valid: true, normalized: '20123456786', check_digit_expected: '6', ... }

validate('MX', 'auto', 'ABC010101AB2');
// { valid: false, reason: 'check digit mismatch', check_digit_expected: '1', ... }

parseCfdi(xmlString);
// { ok: true, version: '4.0', total: '116.00', emisor: { rfc_check: { valid: true } }, ... }
```

`validate(country, type, value)` takes a country code (`AR`, `CL`, `MX`, `BR`, `CO`, `PE`), a type (or `'auto'` to detect it from the length) and a string or number. Spaces, dots, hyphens and slashes are ignored. It always returns an object with `valid`, `reason`, `normalized`, `check_digit_expected`, `check_digit_found` and `flags`.

Run the example and the tests:

```
node examples/validate.js
node tests/run_fixtures.js
```

The fixtures (71 tests) use synthetic IDs generated by the algorithms, plus the institutional RFC `SAT970701NN3` and the generic RFCs `XAXX010101000` / `XEXX010101000`. No real person's ID is used.

## Limits and disclosures

- It checks **format and check digits only**. It does not confirm that an ID is registered or active with any tax authority, and a passing result is not proof that the ID exists.
- It is **not tax, legal or accounting advice**.
- It is independent and **not affiliated with** SAT, AFIP/ARCA, SII, Receita Federal, DIAN or SUNAT. Those names are used only to describe what the code does.
- The code and this README are **AI-assisted**. Correctness rests on the automated fixtures in `tests/`, not on any manual review.
- Inputs are processed in memory; the library stores nothing.

References: [CUIT on Wikipedia](https://en.wikipedia.org/wiki/CUIT), [CPF on Wikipedia](https://en.wikipedia.org/wiki/CPF_number), [CNPJ on Wikipedia](https://en.wikipedia.org/wiki/CNPJ), [CURP on Wikipedia](https://en.wikipedia.org/wiki/Unique_Population_Registry_Code).

## Español

Validadores de IDs fiscales latinoamericanos en JavaScript (Node.js 18+), sin dependencias, más un lector de encabezados de facturas CFDI 3.3 / 4.0 de México. Sin acceso a red ni a archivos.

Este proyecto es construido y mantenido por un sistema automatizado de agentes (en inglés: "This project is built and maintained by an automated agent system.").

**IDs soportados:** CUIT/CUIL (Argentina), RUT (Chile), RFC y CURP (México), CPF y CNPJ, incluido el CNPJ alfanumérico (Brasil), NIT (Colombia) y RUC (Perú). El parser CFDI lee Comprobante, Emisor, Receptor y TimbreFiscalDigital, cuenta los conceptos y valida el dígito verificador de los RFC; no verifica el sello del SAT.

**Uso:** igual que en los ejemplos de arriba: `validate('AR', 'cuit', '20-12345678-6')` y `parseCfdi(xml)`. Pruebas: `node tests/run_fixtures.js`.

**Límites y avisos:**

- Solo comprueba el **formato y los dígitos verificadores**. No confirma que un ID esté registrado ni activo ante ninguna autoridad fiscal.
- **No es asesoramiento fiscal, legal ni contable.**
- Es independiente y **no está afiliado** a SAT, AFIP/ARCA, SII, Receita Federal, DIAN ni SUNAT; esos nombres se usan solo para describir lo que hace el código.
- El código y este README fueron elaborados con **asistencia de IA**. La corrección se apoya en las pruebas automáticas de `tests/`.
- Los datos se procesan en memoria; la librería no guarda nada.
